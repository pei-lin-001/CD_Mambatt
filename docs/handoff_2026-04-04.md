## 一、项目一句话简介

在 MambAtt（Mamba + Attention）骨干上设计跨域 RUL 预测方法，核心创新是 **SPD（Selectivity Projection Disentanglement）**——将 Mamba 内部产生选择性参数 B/C/Δ 的投影层拆分为域不变路径和域特定路径。

## 二、上一轮做了什么

### 2.1 发现并修复了严重的协议 bug

v3 训练脚本缺少三个关键 flag，导致所有先前 SPD 实验的验证集只有 10-20 个样本（应为 2000-3700），checkpoint 选择极不可靠。

**已修复**：`train_cd_mambatt_v3.py` 中三个 flag 默认值改为 True：
- `--source-val-all-windows`
- `--target-val-all-windows`  
- `--resample-few-shot-per-seed`

修复后 SPD 从"看起来不如 v2"变为"首次超过 v2"。详见实验日志第 12 章。

### 2.2 SPD 诊断探针

发现了两个重要事实：
1. **Mamba 隐状态域偏差累积 59 倍**（timestep 1→20, MMD 从 0.014 到 0.805）
2. **SPD 的域解耦效果很弱**（inv vs combined 域分类准确率差距仅 0.3%，gate 只从 0.12 移动到 0.18）

### 2.3 多方向快速实验

测试了 6 个辅助损失方向 + 4 个"大杠杆"方向：

**有效的**：
- Spec 域预测损失（鼓励 spec 分支主动吸收域信息）→ 最好的辅助损失
- LR=2e-3 + cosine schedule → 最大的单一优化改善（-1.5 RMSE）
- 跨域自监督预训练 → 有效但不如调 LR

**无效的**：
- SSDA（隐状态对齐）→ 立即饱和，对 λ 不敏感
- Inv/Spec 正交约束 → 有害
- 时序 Mixup / 目标域增强 → 有害
- d_model=42 → 微小改善

### 2.4 找到当前最优配置

**SPD + inv-MMD + spec域预测 + LR=2e-3 + cosine**：

| 任务 | SPD best | v2 ref | Delta |
|---|---|---|---|
| FD001→FD003 (3s) | **20.37 ± 0.47** | 21.13 ± 1.59 | **-0.76** ✅ |
| FD001→FD004 (3s) | 23.72 ± 2.38 | 24.34 | -0.62 ⚠️ |
| FD003→FD001 (3s) | 21.03 ± 1.70 | 19.81 | **+1.22** ❌ |

### 跑最优配置的命令

```bash
conda run -n cd_mamba python train_cd_mambatt_v3.py \
  --task FD001_TO_FD003 \
  --mamba-block-mode dd_spd \
  --inv-alignment-mode mmd \
  --lambda-inv-mmd 0.1 \
  --lambda-domain-adv 0.0 \
  --domain-feature-tap inv_mean \
  --adaptation-freeze-mode none \
  --spd-predictor-mode shared_head \
  --semantic-warmup-epochs 0 \
  --target-lr 2e-3 \
  --seeds 42,43,44,45,46 \
  --output-dir runs/spd_best_5seed_fd001_fd003
```

注意：`--target-lr 2e-3` 需要配合 cosine schedule，但 v3 脚本可能还没内置 cosine scheduler。如果没有，需要在 v3 的 `fit_cd_pseudo_stage` 中加入 `CosineAnnealingLR`，或者用独立脚本 `experiments/ablations/spd_highlr_3seed.py` 的逻辑。

## 五、目前的核心问题

### 问题 1：SPD 的改善幅度不够大

在 FD001→FD003 上比 v2 好 0.76 RMSE，但这主要来自 LR 调优（-1.5 RMSE），SPD 架构本身的贡献（vs bare）只有 ~0.9 RMSE，且域解耦效果很弱（0.3% 差异）。

### 问题 2：多任务不一致

FD003→FD001 上 SPD 输了 1.22 RMSE。可能原因：
- FD003 只有 100 台发动机做源域，LR=2e-3 可能过于激进导致源域过拟合
- SPD 的 spec 分支在小数据源域上可能引入额外的优化不稳定性

### 问题 3：创新叙事的支撑证据不足

SPD 宣称"域解耦"，但实验证据（gate 变化 0.06, 域分类差异 0.3%）不够强。审稿人可能会质疑这是否真的在做解耦。

## 六、下一步建议（优先级排序）

### P0：诊断 FD003→FD001 的失败

- 在 FD003→FD001 上用 LR=5e-4（原来的默认值）跑 SPD，看是否是 LR 过高导致的退化
- 如果降 LR 后 SPD 至少和 v2 持平，说明问题是任务特定的超参敏感性，不是架构缺陷

### P1：5-seed 扩展

- 在 FD001→FD003 上用最优配置跑 5 seeds（42-46），获得更可靠的统计估计
- 同时跑 v3+bare 5 seeds 作为对照

### P2：消融实验

在匹配协议下，FD001→FD003，5 seeds：
- A: bare（无 SPD，无额外损失）
- B: bare + inv-MMD（验证 inv-MMD 是否需要 SPD 配合）
- C: SPD only（无 inv-MMD，无 spec 域预测）
- D: SPD + inv-MMD（无 spec 域预测）
- E: SPD + inv-MMD + spec 域预测（完整）

### P3：增强域解耦效果

当前解耦太弱。可能的方向：
- 增大 spec 分支的初始化幅度（当前 std=1e-4）
- 加大 spec 域预测损失权重（当前 0.1）
- 尝试 Barlow Twins 风格的冗余缩减损失（来自 CDDG 论文, Neural Networks 2024）
- 在 spec 分支上加显式的域分类监督（使用所有 unlabeled target 数据的 pseudo-domain label）

### P4：15-shot 对比 FOMLN

v2 在 15-shot 上 4/4 赢了 FOMLN。SPD 需要同样的验证。

### P5：论文写作准备

- t-SNE 可视化（inv vs combined vs spec 的域分布）
- 隐状态域偏差累积图（已有数据，需要绘图）
- 消融表格
